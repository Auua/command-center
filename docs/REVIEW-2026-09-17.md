## 1. Learning center: the accepted ADRs describe a repo that does not exist

ADR-024 (and 011/012/013/019/026/032 built on it) specifies a machine-generated layout:
`pool/japanese/*.jsonl` from a `tools/jmdict-ingest` tool, `pool/grammar/*.md` authored in English
front-matter, `progress/<kind>.json` written by the API, `cards/**` one-file-per-card with
`anki: true`, `sync/state.json`, and `tools/anki-sync` as a GitHub Action.

The actual `learning-center` repo is an Obsidian vault, Finnish-first, with its own schema:

| Vault folder                    | Notes | Front-matter `type` | Key fields                                                           |
| ------------------------------- | ----: | ------------------- | -------------------------------------------------------------------- |
| `30 Sanasto/Sanat`              | 7 959 | `vocab`             | word, reading, romaji, meaning (FI), pos, jlpt, kanji, sets, sources |
| `20 Verbit/Lekseemit`           | 1 460 | `verb`              | + verbclass, transitivity, pair, full conjugation table in body      |
| `40 Kanji/Merkit`               | 1 112 | `kanji`             | strokes, onyomi, kunyomi, meaning, components, lookalikes            |
| `10 Kielioppi/Pisteet`          |   317 | `grammar`           | ja, reading, jlpt, func, attaches, compare, sources                  |
| `50 Lauseet`                    |    81 | `sentences`         | example banks with `^block-ids`, embedded elsewhere                  |
| `30 Sanasto/Setit`              |    64 | `set`               | theme sets, Bases-driven                                             |
| `60 Lahteet`                    |    19 | `source`            | textbooks/sites with chapter → grammar links                         |
| `90 Paivakirja/Loki`, `Virheet` |   2+2 | `log`, `mistake`    | minutes, materials, focus / topic, cause, recurring, fixed           |

Every content note carries `status: new|learning|shaky|known`, `confidence: 1–5`, `reviewed: date`.
Every note has a `## Kortit` section in Obsidian Spaced-Repetition syntax (`#flashcards/...`,
`Front::Back`, multi-line `?`), and `00 Meta/Scripts/sr_to_anki.py` already exports them to an Anki
TSV with a stable sha1 UID and a `Japani (Obsidian)` note type. `check_vault.py` already parses the
front-matter schema. Views are Obsidian Bases (`00 Meta/Bases/*.base`); `Kertaus.base` is the review
dashboard ("weakest first", "not reviewed in 30 days", "recurring mistakes").

ADR-024 explicitly rejected "Obsidian-vault-in-Git" as an alternative. The product owner then built
exactly that, with 10× the content the JMdict pool would have provided. The ADRs need to follow.

### Proposed direction (for a new ADR-040, superseding ADR-024's layout section)

- **Pool = the vault's typed notes.** WOTD eligible set = `type: vocab|verb` (and later `kanji`)
  with `status: new`, filtered by a `jlptCeiling` setting. No JMdict ingest, no `pool/` shards, no
  `tools/jmdict-ingest`. Attribution (ADR-032) simplifies: content is the user's own notes from
  owned textbooks; EDRDG rows disappear from the manifest.
- **Progress = the vault's own fields, not `progress/<kind>.json`.** Acknowledge writes
  `status: learning`, `reviewed: <date>`, and bumps `confidence`; skip writes `status: known`.
  This keeps `Kertaus.base` honest in Obsidian (today `reviewed` is set on 0 of 10 858 notes and
  `confidence` is 1 on 10 750, so the vault's review views are empty by construction). The app
  becomes the thing that populates them.
- **Cards = `## Kortit`, not `cards/**`.** "Add to Anki" for a note the vault already has means:
  the card already exists; the action is "include in next export". Either flag it (`anki: true` in
  front-matter, matching ADR-026's flag) or drop the action for vault notes and keep it only for
  content that has no note yet. ADR-026's sync Action should run `sr_to_anki.py` (or a TS port) and
  import the TSV with the `anki` library, keeping the vault's sha1 UID as the guid instead of
  `cc:<id>`; note type `Japani (Obsidian)` replaces `CC Japanese v1`.
- **Grammar widget (ADR-012)** reads `10 Kielioppi/Pisteet`. There is no `sequence` field; order
  by `jlpt` then `sources` chapter (`[[Minna no Nihongo Chuukyuu II#Luku 20]]` sorts naturally) or
  `created`. Examples are block embeds (`![[Lausepankki — X#^id]]`) into `50 Lauseet`; the API must
  resolve `^block-id` references, which is a small parser, not a content change.
- **Reading path at 14 000 files.** Per-file Contents API reads do not scale; ADR-024's cache
  assumed a handful of shards. Two workable options: (a) a vault-side GitHub Action (path-filtered,
  reusing `check_vault.py`'s parser) that emits `.cc/index/{vocab,verb,kanji,grammar}.jsonl` from
  front-matter on every push, and the API reads only those — this preserves ADR-024's shard read
  path unchanged; (b) the API fetches the repo tarball at a SHA once per refresh. (a) is smaller and
  keeps GitHub off the hot path. Writes stay per-file `PUT` with sha guard (front-matter edits are
  a few lines).
- **Language.** Widget UI stays English; content is FI-first with EN in the body. Add
  `meaningLanguage: fi|en` to the WOTD/grammar settings; default `fi`.
- **Furigana.** The vault stores `reading` as kana, not bracket furigana. Render `<ruby>word<rt>reading</rt></ruby>` for single-token headwords; bracket furigana (ADR-024) is only needed for sentences, which come from `50 Lauseet` without alignment anyway (already accepted as plain).
- **Concurrency with obsidian-git.** The vault auto-commits ("vault backup: …"). API writes must
  land on `main` with sha-guarded retries and the vault must auto-pull before commit, or the
  next backup push rejects. Worth stating as a runbook rule.
- **New widget candidates the vault makes cheap:** "Recurring mistakes" (from `Virheet`,
  `recurring: true, fixed: false`), "Study log" (append to `90 Paivakirja/Loki/<date>.md` with
  minutes/materials — a natural `learning.logged` streak source in place of `wotd.acknowledged`
  alone), and a kanji-of-the-day sibling of WOTD.
- **Docs to amend:** ADR-024 (layout + alternatives), 011, 012, 013 (`pool/tech/` can stay — the
  vault has no tech area yet; note that tech content would live as a sibling top-level folder),
  019, 026 (note types, guid, import mode), 032 (attribution), `docs/runbook-learning-center.md`
  (steps 6–8 change), ADR.md §3 container diagram, §4.3/§4.5 prose, §7 rows.
